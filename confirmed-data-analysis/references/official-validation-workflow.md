# 官方值对账流程

## 目的

在数据分析完成后，将计算值与用户提供的官方大盘值进行对账。该步骤用于发现查询口径、数据覆盖或加工链路问题，不能用官方值覆盖计算结果。

## 执行位置

```text
数据获取 → 数据画像 → 分析计算 → 官方值对账 → 业务解释 → 输出与交接
```

## 第一步：匹配指标

按 `metric_name` 匹配计算指标与官方指标。存在别名时，应先使用已确认的指标别名映射；禁止仅按模糊字符串自动匹配。

没有匹配到计算指标时，状态为 `missing_computed_value`。

## 第二步：检查可比性

逐项检查：

1. 指标公式
2. 聚合方式
3. 去重键
4. 单位和数值尺度
5. 时间范围
6. 过滤条件和业务范围
7. 时区
8. 数据截止时间

如果策略要求严格匹配，任一关键项为 `mismatch` 时，状态为 `incomparable`，不计算差异等级。

`unknown` 不等于 `match`。关键口径未知时默认进入 `assist` 并询问用户。

## 第三步：计算差异

```text
signed_difference = computed_value - official_value
absolute_difference = abs(signed_difference)
relative_difference = absolute_difference / abs(official_value)
```

当 `official_value = 0` 时，相对差异为 `null`：

- `absolute_only`：仅使用绝对阈值
- `exact_match`：只有计算值也为0才通过

## 第四步：确定阈值

优先级从高到低：

1. 单条官方值的 `tolerance_override`
2. `official_validation_policy.default_tolerance`
3. 产品默认值

产品默认相对阈值：

- `relative_warning = 0.05`
- `relative_critical = 0.10`

默认采用 `any_exceeds`：绝对差异或相对差异任一超过阈值，即进入对应等级。

实现层必须额外校验：`critical` 阈值不得小于对应的 `warning` 阈值。

## 第五步：输出状态

| 状态 | 含义 |
|---|---|
| `not_requested` | 用户未提供官方值 |
| `passed` | 所有可比指标均在警告阈值内 |
| `warning` | 至少一个指标超过警告阈值，但没有达到严重阈值 |
| `critical` | 至少一个指标达到严重阈值 |
| `partial` | 部分指标完成比较，部分缺失或不可比 |
| `incomparable` | 没有指标满足安全比较条件 |

## 第六步：差异诊断

出现 `warning` 或 `critical` 时，按顺序排查：

1. 时间范围和分区是否完整
2. 是否包含当天未完整数据
3. 官方值与查询值的过滤条件是否相同
4. 用户、设备或订单去重方式是否相同
5. 比率是否采用相同分子、分母和聚合方法
6. 时区和自然日边界是否一致
7. 是否存在迟到数据、回补或离线任务延迟
8. 币种、税口径和单位尺度是否一致
9. 官方值本身的更新时间是否落后

每个可能原因都必须附带检查结果，不能只输出原因列表。

## 对结论的影响

- `passed`：可以正常输出分析结论。
- `warning`：保留结论，同时展示校验警告。
- `critical`：默认进入 `assist`；展示计算结果，但阻止无警告的强结论。
- `incomparable`：不宣称数据异常，先解释缺少哪些可比条件。

## 最小输出表

| 指标 | 计算值 | 官方值 | 有符号差异 | 绝对差异 | 相对差异 | 状态 | 口径检查 |
|---|---:|---:|---:|---:|---:|---|---|

汇总必须同时报告请求校验数、完成比较数、通过数、警告数、严重数和不可比数。
